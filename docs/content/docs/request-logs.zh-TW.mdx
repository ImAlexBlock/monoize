## 日誌列表

開啟側邊欄中的**日誌**。Monoize 為每個通過 API 金鑰認證的轉發請求記錄一行。每行顯示：

- 邏輯模型和 API 金鑰名稱；管理員還可以查看提供服務的 Provider 和 Channel；
- Token 數量：輸入、輸出、快取讀取、快取建立和推理 Token；
- 以美元計的費用；
- 狀態：`pending`、`success`、`error` 或 `client_gone`；
- 時間指標：總耗時、首位元組時間，以及串流請求的每秒 Token 數。

列表預設開啟即時更新。關閉**即時更新**可停止事件串流和備援輪詢。使用**重新整理**可手動更新列表。

## 實際上游模型

使用 `admin` 或 `super_admin` 帳戶時，不同的上游回應模型會顯示在模型徽章後方，與徽章位於同一行。
將游標移到模型徽章或 Channel 上，查看**實際模型**。
此值取自回應變換前的上游回應。
Monoize 會將它與請求變換後傳送給上游的模型名稱比較。
如果名稱相同，或回應未宣告模型，則不顯示此值。
其他角色不會收到或看到此值。
邏輯模型和計費選擇維持不變。

## 失敗的嘗試

當一個請求經過多次上游嘗試時，該行會按順序列出每一跳失敗記錄。每一跳顯示 Provider、Channel、上游狀態碼和錯誤文字。透過這個列表可以看到哪個 Channel 失敗了，以及請求為什麼繼續前進。

## 請求擷取

擷取功能把每次上游嘗試的完整封包儲存到磁碟。擷取預設關閉。兩個開關控制它：

1. **系統開關。** `super_admin` 在**設定**中啟用請求擷取。系統開關關閉時，任何金鑰都不會寫入擷取檔案。
2. **金鑰級模式。** 每個 API 金鑰設定 `request_capture_mode`：
   - `off`：從不擷取。
   - `capture-all`：擷取每個到達上游的請求。
   - `capture-only-abnormal`：擷取失敗、缺少用量、用量為零或發生多次上游嘗試的請求。

擷取檔案有保留期。預設為 1 天。在**設定**中修改 `monoize_request_capture_retention_days` 可以調整。

## 擷取檢視器

有擷取記錄的行會顯示擷取標記。點擊標記開啟檢視器。檢視器為每次嘗試顯示：

- 原始的下游請求主體；
- 經過所有變換後的請求；
- 編碼後發往上游的完整請求；
- 上游的原始回應或串流幀；
- 實際執行的變換鏈，包括範圍和順序。

`user` 角色只能檢視自己的擷取，且只能看到 API 金鑰範圍的變換條目。管理員可以檢視 `user` 角色帳戶的擷取。

## 疑難排解

| 現象 | 原因 | 處理 |
| --- | --- | --- |
| 新行沒有擷取標記 | 擷取持久化晚於即時行到達 | 等待列表自動重新整理，或重新整理一次頁面 |
| `capture_not_found` | 擷取已過期，或你的角色無權檢視 | 提高保留天數，或聯絡擷取所有者 |
| 某個金鑰的行缺失 | 該金鑰屬於其他使用者 | 以金鑰所有者或管理員身分登入 |
