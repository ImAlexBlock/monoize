## ベース URL と認証

リクエストは Monoize のリッスンアドレスに送信します。デフォルトは `http://localhost:8080` です。API キーは次のいずれかのヘッダーで送信します。

```bash
Authorization: Bearer sk-...
# または
x-api-key: sk-...
```

以下の各エンドポイントには `/api` プレフィックスの別名があります。例: `/api/v1/chat/completions`。クライアントが `/api` パスを固定している場合に別名を使います。サイトのルートを API Base URL に設定したクライアントは `/v1` を省略でき、`/responses` などを使用できます。

どのエンドポイントも任意の上流タイプに到達できます。たとえば、クライアントが `/v1/messages` を呼び出し、ルートが `chat_completion` タイプの Channel でそのモデルを提供する構成が可能です。Monoize は双方向でプロトコルを変換します。

## プロトコル変換

複数のツールで同じ名前を使う場合は、Responses のツール名前空間を指定してください。選択した Channel が Chat Completions、Messages、Gemini を使う場合も、ツールの識別情報を保持します。

プロバイダー間でファイルを渡す場合は、ファイル本体または公開 URL を指定してください。非公開ファイルの参照には、Provider、Channel、認証情報の範囲が一致する単一の経路が必要です。

画像マスクは元の画像と一緒に送信してください。画像変換ではマスクの寸法と透明度を保持します。

変換先のプロトコルで応答のメディアを表現できない場合は、明示的なエラーを返します。ストリーミング応答は成功イベントではなく、エラーで終了します。

Gemini の変換では、対応するサンプリング設定、引用、ツール署名、使用量の詳細を保持します。プロトコル固有のフィールドは互換性のある宛先にのみ送信します。

## モデル一覧

```bash
curl http://localhost:8080/v1/models \
  -H "Authorization: Bearer sk-..."
```

レスポンスは、呼び出したキーが利用できる論理モデルを OpenAI のリスト形式で返します。

## Chat Completions

```bash
curl http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-model",
    "messages": [{ "role": "user", "content": "Hello" }],
    "stream": true
  }'
```

`"stream": true` を設定するとサーバー送信イベントを使います。省略または `false` にすると単一の JSON レスポンスを返します。

## Responses

```bash
curl http://localhost:8080/v1/responses \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-model",
    "input": "Hello",
    "stream": true
  }'
```

補足:

- 上流がサーバー側状態を提供する場合、Monoize は `previous_response_id` チェーンをサポートします。セッションアフィニティを有効にすると、後続リクエストが同じ Channel に到達します。[ルーティングと信頼性](/ja/docs/routing)を参照してください。
- `GET /v1/responses` は WebSocket トランスポートにアップグレードされます。
- `GET /v1/codex/responses` は `GET /v1/responses` と同じ WebSocket ハンドラーを使います。`POST /v1/codex/responses` は `POST /v1/responses` と同じ HTTP ハンドラーを使います。両方のパスには `/api` エイリアスもあります。
- `POST /v1/responses/compact` は会話をコンパクト化します。

Responses 上流へのリクエストでは、Monoize は明示された `include` と `reasoning.summary` の値を保持します。`reasoning.encrypted_content` や既定の要約設定は自動で追加しません。

## Anthropic Messages

```bash
curl http://localhost:8080/v1/messages \
  -H "x-api-key: sk-..." \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-model",
    "max_tokens": 1024,
    "messages": [{ "role": "user", "content": "Hello" }]
  }'
```

## Embeddings

curl http://localhost:8080/v1/embeddings \

## 画像

Responses Channel で画像エンドポイントを使う前に、`image_enable_openai_generation_tool` を設定してください。必要なツールがないリクエストは、転送前にエラーを返します。

生成:

```bash
curl http://localhost:8080/v1/images/generations \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-image-model",
    "prompt": "A lighthouse at dawn",
    "size": "1024x1024"
  }'
```

編集は `multipart/form-data` を使います。

```bash
curl http://localhost:8080/v1/images/edits \
  -H "Authorization: Bearer sk-..." \
  -F model="my-image-model" \
  -F prompt="Add a red boat" \
  -F image[]=@input.png
```

## 公式 SDK の利用

公式 SDK のベース URL を Monoize に向けます。

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8080/v1",
    api_key="sk-...",
)
```

```python
import anthropic

client = anthropic.Anthropic(
    base_url="http://localhost:8080",
    api_key="sk-...",
)
```

## エラーレスポンス

| HTTP ステータス | コード | 意味 |
| --- | --- | --- |
| `401` | `unauthorized` | API キーが未指定、無効、無効化済み、または期限切れ |
| `402` | `insufficient_balance` | ユーザーまたはサブアカウントの残高が不足 |
| `402` | `api_key_spend_limit_reached` | キーの利用上限ウィンドウ(合計・時間・日次)を使い切りました |
| `403` | `model_not_allowed` | キーのモデル制限が要求モデルを拒否 |
| `403` | `ip_not_allowed` | クライアント IP がキーの IP ホワイトリストにない |
| `502` | `upstream_error` | モデルを提供するルートがない、または適格なルートがすべて失敗 |

上流のエラーテキストはクライアントに届く前にサニタイズされます。完全な詳細は[リクエストログ](/ja/docs/request-logs)で確認できます。
