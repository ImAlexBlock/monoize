## What an API key does

Clients authenticate forwarding requests with an API key. Every key starts with `sk-`. Send the key in one of these headers:

```bash
Authorization: Bearer sk-...
# or
x-api-key: sk-...
```

Requests without a valid key receive HTTP `401`.

![API key management](/images/en/api-keys.webp)

## Create a key

1. Open **Token Management** in the sidebar.
2. Click the create button and enter a name.
3. Set the options you need. All options have safe defaults.
4. Copy the full key. The list shows the full key again later; keys are not write-only in Monoize.

## Key options

| Option | Effect | Default |
| --- | --- | --- |
| Expiry | The key stops working after the expiry date. | No expiry |
| Enabled | A disabled key fails authentication at once. | Enabled |
| Model limits | When on, the key can call only the listed model patterns. | Off |
| IP whitelist | When set, requests must come from a listed IPv4/IPv6 address or CIDR range. | Empty |
| Groups | The key routes only to Providers in the allowed Groups. | All Groups accessible to the owner |
| Max multiplier | The key skips Provider-model mappings whose effective multiplier exceeds this value. | No cap |
| Spend limits | Total, hourly, and daily spend windows in USD. Empty means unlimited. The daily badge shows `spent/limit`. | Unlimited |
| Request capture | `off`, `capture-all`, or `capture-only-abnormal`. See [Request Logs](/en/docs/request-logs). | `off` |

## Spend limits

Each key carries three spend-limit windows: total (lifetime), hourly (a rolling
hour), and daily (a UTC calendar day). Charges bill the user wallet as usual;
a limit stops serving the key with HTTP `402` `api_key_spend_limit_reached`
once a window is exhausted. The key list shows one badge per configured
window, and the daily badge shows `spent/limit`. Limits accept USD or CNY
input; a CNY amount converts through the current exchange rate when you save.
Legacy keys that still hold an independent balance keep settling against it
until the balance reaches zero or the key is deleted.

Enter amounts with up to nine decimal places. Conversion preserves exact decimal values and rounds once to the nearest nano-USD; ties round up.
Monoize disables CNY input and shows a warning when the exchange rate is missing or invalid.

## Model limits

Model limit entries are exact logical model names. A request whose model equals no entry receives HTTP `403` with code `model_not_allowed`.

## Model redirects

A key can hold an ordered list of model redirect rules. Each rule has:

- `pattern`: a regular expression. Monoize anchors it as `^(pattern)$` against the full model name.
- `replace`: the literal target model name.

The first matching rule rewrites the model before routing, billing, and model-limit checks. Key rules run before global rules. Use redirects to move traffic to a new model without client changes.

## Groups

- Leave the selection empty to use all Groups accessible to the owner.
- Select one or more Groups to restrict the key. Monoize prefers Providers from earlier Groups. See [Routing and Reliability](/en/docs/routing).

An enabled billing plan with a non-empty Group list restricts both selections to its Groups.
If the key and plan have no Group in common, requests receive HTTP `401`.
The owner's single Group does not determine this selection.

## Per-key transforms

A key can hold an ordered transform chain. Key transforms run inside a safety boundary: only transform types allowed at API-key scope are accepted. See [Transforms](/en/docs/transforms).

## Review key usage

Select a key row to open the usage dialog. The dialog stays on the API keys page and never navigates away.

Choose Today, the last 7 days, the last 30 days, or all retained history. Today covers the current Beijing calendar day from 00:00 and uses hourly buckets. The 7-day and 30-day ranges use daily buckets. All history uses monthly buckets when the retained span exceeds 90 days and daily buckets otherwise.

The dialog reports total Tokens, input Tokens, cache-read Tokens, output Tokens, call count, consumed Coin, the key balance, a trend, and a model breakdown. Model rows sort by total Tokens descending, then by model name ascending.

Consumed Coin is the sum of the recorded charges. Monoize never recomputes a historical charge from a current price. Every key shows **Follows wallet balance**; keys no longer carry their own balance. A disabled or expired key keeps its readable history.
