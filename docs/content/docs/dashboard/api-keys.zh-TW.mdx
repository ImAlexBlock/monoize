## API 金鑰的作用

用戶端使用 API 金鑰認證轉發請求。每個金鑰都以 `sk-` 開頭。金鑰可以放在以下任一請求標頭中：

```bash
Authorization: Bearer sk-...
# 或
x-api-key: sk-...
```

沒有有效金鑰的請求會收到 HTTP `401`。

![API 金鑰管理](/images/en/api-keys.webp)

## 建立金鑰

1. 開啟側邊欄中的**令牌管理**。
2. 點擊建立按鈕並輸入名稱。
3. 依需求設定選項。所有選項都有安全的預設值。
4. 複製完整金鑰。列表之後仍會顯示完整金鑰；Monoize 的金鑰不是一次性展示。

## 金鑰選項

| 選項 | 效果 | 預設值 |
| --- | --- | --- |
| 過期時間 | 到期後金鑰停止運作。 | 永不過期 |
| 啟用 | 停用的金鑰立即無法通過認證。 | 啟用 |
| 模型限制 | 開啟後，金鑰只能呼叫列出的模型模式。 | 關閉 |
| IP 白名單 | 設定後，請求必須來自列出的 IPv4/IPv6 位址或 CIDR 網段。 | 空 |
| 群組 | 金鑰只路由到允許的 Group 中的 Provider。 | 所屬使用者可存取的全部 Group |
| 倍率上限 | 金鑰跳過有效倍率超過該值的 Provider 模型對應。 | 無上限 |
| 消費限額 | 總額、每小時、每日三個消費視窗，單位 USD。留空表示不限制。每日徽章顯示 `已用/限額`。 | 不限制 |
| 請求擷取 | `off`、`capture-all` 或 `capture-only-abnormal`。參見[請求日誌](/zh-TW/docs/request-logs)。 | `off` |

## 消費限額

每個金鑰有三個消費限額視窗：總額（累計）、每小時（滾動一小時）、每日（UTC 自然日）。費用照常從使用者錢包扣款；視窗用盡後金鑰以 HTTP `402` `api_key_spend_limit_reached` 停止服務。金鑰列表為每個已配置的視窗顯示一枚徽章，每日徽章顯示 `已用/限額`。限額支援 USD 或 CNY 輸入；CNY 金額在儲存時按目前匯率換算。仍持有獨立餘額的舊金鑰會繼續從該餘額結算，直到歸零或刪除。

金額最多可輸入九位小數。換算使用精確十進位值，最後四捨五入至 nano-USD。
匯率缺失或無效時，Monoize 停用 CNY 輸入並顯示提示。

## 模型限制

模型限制條目是精確的邏輯模型名。模型不等於任何條目的請求會收到 HTTP `403`，錯誤碼為 `model_not_allowed`。

## 模型重新導向

金鑰可以持有一個有序的模型重新導向規則列表。每條規則包含：

- `pattern`：正規表示式。Monoize 以 `^(pattern)$` 的形式對完整模型名做錨定匹配。
- `replace`：字面量目標模型名。

第一條匹配的規則在路由、計費和模型限制檢查之前重寫模型名。金鑰規則先於全域規則執行。使用重新導向可以在不修改用戶端的情況下把流量切換到新模型。

## 群組

- 留空時，金鑰使用所屬使用者可存取的全部 Group。
- 選擇一個或多個 Group 來限制金鑰。Monoize 優先選擇排序靠前的 Group 中的 Provider。參見[路由與可靠性](/zh-TW/docs/routing)。

若啟用的計費方案設有非空 Group 清單，兩種選擇都受該清單限制。
金鑰與方案沒有共同的 Group 時，請求傳回 HTTP `401`。
使用者本身的單一 Group 不決定此選擇。

## 金鑰級變換

金鑰可以持有一個有序的變換鏈。金鑰級變換受安全邊界約束：只接受允許在 API 金鑰範圍使用的變換類型。參見[變換](/zh-TW/docs/transforms)。

## 檢視金鑰用量

選擇一列金鑰即可開啟用量對話框。對話框停留在 API 金鑰頁面，不會跳轉。

選擇今日、最近 7 天、最近 30 天或全部保留歷史。今日範圍覆蓋北京時間當日 00:00 起，按小時分桶。7 天和 30 天範圍按天分桶。全部歷史在保留跨度超過 90 天時按月分桶，否則按天分桶。

對話框顯示總 Tokens、輸入 Tokens、快取讀取 Tokens、輸出 Tokens、呼叫次數、消耗的 Coin、Key 餘額、趨勢和模型明細。模型列按總 Tokens 遞減排序，再按模型名稱遞增排序。

消耗的 Coin 是已記錄扣費的總和。Monoize 不會用目前價格重新計算歷史扣費。每個 Key 都顯示**跟隨錢包餘額**；金鑰不再持有自己的餘額。已停用或已過期的 Key 仍可檢視歷史。
