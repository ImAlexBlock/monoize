## API 密钥的作用

客户端使用 API 密钥认证转发请求。每个密钥都以 `sk-` 开头。密钥可以放在以下任一请求头中：

```bash
Authorization: Bearer sk-...
# 或
x-api-key: sk-...
```

没有有效密钥的请求会收到 HTTP `401`。

![API 密钥管理](/images/zh/api-keys.webp)

## 创建密钥

1. 打开侧边栏中的**令牌管理**。
2. 点击创建按钮并输入名称。
3. 按需设置选项。所有选项都有安全的默认值。
4. 复制完整密钥。列表之后仍会显示完整密钥；Monoize 的密钥不是一次性展示。

## 密钥选项

| 选项 | 效果 | 默认值 |
| --- | --- | --- |
| 过期时间 | 到期后密钥停止工作。 | 永不过期 |
| 启用 | 禁用的密钥立即无法通过认证。 | 启用 |
| 模型限制 | 开启后，密钥只能调用列出的模型模式。 | 关闭 |
| IP 白名单 | 设置后，请求必须来自列出的 IPv4/IPv6 地址或 CIDR 网段。 | 空 |
| 分组 | 密钥只路由到允许的 Group 中的 Provider。 | 所属用户可访问的全部 Group |
| 倍率上限 | 密钥跳过有效倍率超过该值的 Provider 模型映射。 | 无上限 |
| 消费限额 | 总额、每小时、每日三个消费窗口，单位 USD。留空表示不限制。每日徽章显示 `已用/限额`。 | 不限制 |
| 请求捕获 | `off`、`capture-all` 或 `capture-only-abnormal`。参见[请求日志](/zh/docs/request-logs)。 | `off` |

## 消费限额

每个密钥有三个消费限额窗口：总额（累计）、每小时（滚动一小时）、每日（UTC 自然日）。费用照常从用户钱包扣款；窗口用尽后密钥以 HTTP `402` `api_key_spend_limit_reached` 停止服务。密钥列表为每个已配置的窗口显示一枚徽章，每日徽章显示 `已用/限额`。限额支持 USD 或 CNY 输入；CNY 金额在保存时按当前汇率换算。仍持有独立余额的旧密钥会继续从该余额结算，直到清零或删除。

金额最多可输入九位小数。换算使用精确十进制值，最后四舍五入到 nano-USD。
汇率缺失或无效时，Monoize 禁用 CNY 输入并显示提示。

## 模型限制

模型限制条目是精确的逻辑模型名。模型不等于任何条目的请求会收到 HTTP `403`，错误码为 `model_not_allowed`。

## 模型重定向

密钥可以持有一个有序的模型重定向规则列表。每条规则包含：

- `pattern`：正则表达式。Monoize 以 `^(pattern)$` 的形式对完整模型名做锚定匹配。
- `replace`：字面量目标模型名。

第一条匹配的规则在路由、计费和模型限制检查之前重写模型名。密钥规则先于全局规则执行。使用重定向可以在不修改客户端的情况下把流量切换到新模型。

## 分组

- 留空时，密钥使用所属用户可访问的全部 Group。
- 选择一个或多个 Group 来限制密钥。Monoize 优先选择排序靠前的 Group 中的 Provider。参见[路由与可靠性](/zh/docs/routing)。

如果启用的计费套餐设有非空 Group 列表，两种选择都受该列表限制。
密钥与套餐没有共同的 Group 时，请求返回 HTTP `401`。
用户自身的单一 Group 不决定此选择。

## 密钥级变换

密钥可以持有一个有序的变换链。密钥级变换受安全边界约束：只接受允许在 API 密钥范围使用的变换类型。参见[变换](/zh/docs/transforms)。

## 查看密钥用量

选择一行密钥即可打开用量对话框。对话框停留在 API 密钥页面，不会跳转。

选择今日、最近 7 天、最近 30 天或全部保留历史。今日范围覆盖北京时间当日 00:00 起，按小时分桶。7 天和 30 天范围按天分桶。全部历史在保留跨度超过 90 天时按月分桶，否则按天分桶。

对话框显示总 Tokens、输入 Tokens、缓存读取 Tokens、输出 Tokens、调用次数、消耗的 Coin、Key 余额、趋势和模型明细。模型行按总 Tokens 降序排序，再按模型名升序排序。

消耗的 Coin 是已记录扣费的总和。Monoize 不会用当前价格重新计算历史扣费。每个 Key 都显示**跟随钱包余额**；密钥不再持有自己的余额。已停用或已过期的 Key 仍可查看历史。
