## Logical models

Clients request a logical model name. Monoize resolves that name against your Providers and Channels. The name your clients see never has to match an upstream vendor name.

One logical model can map to the Channel of several Providers. This gives you failover without client changes.

## Redirects

A Channel model entry can set `redirect` to the real upstream model name.

Example: clients call `my-fast-model`. One Provider redirects it to `gpt-4o-mini`. Another Provider redirects it to `claude-3-5-haiku-20241022`. Billing and logs always show the logical name.

For `admin` and `super_admin` accounts, request logs also show a differing upstream response model beside the logical model badge.
Hover the model badge or Channel to inspect **Actual Model**. This value does not change billing.
See [Request Logs](/en/docs/request-logs#actual-upstream-model).

## Model metadata and pricing

The **Models** page is a single master-detail workbench. The toolbar selects the Billing Profile, searches models, and opens the sync, match-rule, and profile-management actions. The master list shows one row per model with a compressed price summary. Select a row to edit its prices in the right panel.

Billing uses:

1. select the model mapping's effective Billing Profile;
2. select a complete rate matrix for the upstream or logical model;
3. apply the model multiplier override or the Provider multiplier.

Each rate record stores a price and a price currency. The price editor has a `CNY`/`USD`
selector; the digits you type are interpreted directly in that currency with no exchange-rate
conversion. A rate imported from Models.dev keeps `USD`.

The editor sets an off-peak price and an optional peak price per usage class, including cache
write 5m and cache write 1m lanes. The peak price applies only on Monday through Friday,
`09:00–12:00` and `14:00–18:00` Beijing time (UTC+08:00). Leave the peak field empty to always
bill at the off-peak price.

Monoize converts a `CNY` price with the current CNY/USD exchange-rate snapshot and
accumulates charges in nano-dollars in each user's ledger. If a model uses a `CNY` price and
no exchange-rate snapshot is available, requests for that model fail with
`model_pricing_required` instead of being charged at a guessed rate.

## Model listing

`GET /v1/models` returns the logical models available to the calling API key. The result reflects key model restrictions and group membership.

## Model globs

Transform rules and some restrictions accept model glob patterns:

- `*` matches any sequence of characters, including an empty one.
- `?` matches exactly one character.
- Matching is case-sensitive and anchored to the full model name.

Example: `gpt-4*` matches `gpt-4o` and `gpt-4o-mini`. It does not match `o4-mini`.


## Manage pricing profiles

Open **Profiles** in the toolbar. Each profile lists its model and rate counts.

- **Copy** duplicates every rate row under a new profile name.
- **Delete** removes the profile and all of its rate rows. A profile referenced by a match rule or a Provider refuses deletion with the reason shown inline.

## Sync prices

Open **Sync** in the toolbar and choose **Sync models.dev** or **Sync catalog**. After the sync
finishes, a report shows how many models were upserted, how many were removed, and which
models kept their manual prices. Manual prices are never overwritten by a sync.


## Add a model price directly

Open **Add price** in the toolbar, type the model name, and fill the price lanes in the
right panel. The model does not need registry metadata, and the profile is not tied to one
channel — every Provider that routes this model through the profile bills these prices.


## Share a profile across account classes

A pricing profile is not exclusive to one account class. Any Provider can reference any
profile name. Price isolation stays intact because every request only resolves the
profiles of its own class's Providers; sharing one profile across classes simply bills
both classes the same prices. Create per-class profile copies when classes need
different prices.

## Model limits

The price editor's **Model limits** card sets the context window and token caps
(max input, max output, max total). Leave a field blank for unlimited. Saving creates
the metadata record when none exists, so limits can be set together with a new price.
