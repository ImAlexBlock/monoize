## API キーの役割

クライアントは API キーで転送リクエストを認証します。すべてのキーは `sk-` で始まります。キーは次のいずれかのヘッダーで送信します。

```bash
Authorization: Bearer sk-...
# または
x-api-key: sk-...
```

有効なキーのないリクエストは HTTP `401` を受け取ります。

![API キー管理](/images/en/api-keys.webp)

## キーの作成

1. サイドバーの**トークン管理**を開きます。
2. 作成ボタンをクリックし、名前を入力します。
3. 必要なオプションを設定します。すべてのオプションに安全なデフォルト値があります。
4. 完全なキーをコピーします。一覧には後からも完全なキーが表示されます。Monoize のキーは一度きりの表示ではありません。

## キーのオプション

| オプション | 効果 | デフォルト |
| --- | --- | --- |
| 有効期限 | 期限を過ぎるとキーは動作を停止します。 | 無期限 |
| 有効化 | 無効化したキーは直ちに認証に失敗します。 | 有効 |
| モデル制限 | 有効にすると、キーは列挙したモデルパターンのみ呼び出せます。 | 無効 |
| IP ホワイトリスト | 設定すると、リクエストは列挙した IPv4/IPv6 アドレスまたは CIDR 範囲からのみ許可されます。 | 空 |
| グループ | キーは許可された Group 内の Provider にのみルーティングされます。 | 所有者がアクセスできるすべての Group |
| 倍率上限 | 有効な倍率がこの値を超える Provider モデル対応付けをスキップします。 | 上限なし |
| 利用上限 | 合計・時間・日次の 3 つの利用上限ウィンドウ（USD）。空欄は無制限。日次バッジは `使用量/上限` を表示します。 | 無制限 |
| リクエストキャプチャ | `off`、`capture-all`、`capture-only-abnormal`。[リクエストログ](/ja/docs/request-logs)を参照してください。 | `off` |

## 利用上限

各キーには 3 つの利用上限ウィンドウがあります。合計（累計）、時間（直近 1 時間）、日次（UTC 暦日）です。課金は通常どおりウォレットから行われ、ウィンドウを使い切ると HTTP `402` `api_key_spend_limit_reached` で停止します。キー一覧は設定済みウィンドウごとにバッジを表示し、日次バッジは `使用量/上限` を示します。上限は USD または CNY で入力でき、CNY 金額は保存時に現在のレートで換算されます。独立残高を保持する既存キーは、残高がゼロになるか削除されるまでその残高から決済され続けます。

金額は小数点以下 9 桁まで入力してください。換算には正確な十進数を使用し、最後に nano-USD 単位へ四捨五入します。
為替レートが未設定または無効な場合、Monoize は CNY 入力を無効にして警告を表示します。

## モデル制限

モデル制限のエントリは正確な論理モデル名です。どのエントリとも一致しないモデルのリクエストは HTTP `403`（エラーコード `model_not_allowed`）を受け取ります。

## モデルリダイレクト

キーは順序付きのモデルリダイレクトルールを保持できます。各ルールの内容は次のとおりです。

- `pattern`: 正規表現。Monoize は完全なモデル名に対して `^(pattern)$` として固定一致させます。
- `replace`: リテラルのターゲットモデル名。

最初に一致したルールが、ルーティング・課金・モデル制限チェックの前にモデル名を書き換えます。キーのルールはグローバルルールより先に実行されます。リダイレクトを使うと、クライアントを変更せずにトラフィックを新しいモデルへ移せます。

## グループ

- 選択を空にすると、所有者がアクセスできるすべての Group を使用します。
- キーの範囲を制限するには、1 つ以上の Group を選択してください。Monoize は先頭に近い Group の Provider を優先します。[ルーティングと信頼性](/ja/docs/routing)を参照してください。

有効な請求プランに Group が指定されている場合、どちらの選択もその Group の範囲に制限されます。
キーとプランに共通の Group がない場合、リクエストは HTTP `401` を返します。
所有者自身に設定された単一の Group は、この選択に影響しません。

## キー単位の変換ルール

キーは順序付きの変換チェーンを保持できます。キー単位の変換には安全境界があり、API キースコープで許可された変換タイプのみ受け付けます。[変換ルール](/ja/docs/transforms)を参照してください。

## キーの使用量を確認する

キーの行を選択すると使用量ダイアログが開きます。ダイアログは API キーのページにとどまり、画面遷移しません。

今日、直近 7 日間、直近 30 日間、または保持されているすべての履歴を選択します。今日の範囲は北京時間の当日 00:00 からの 1 時間単位で集計します。7 日間と 30 日間の範囲は 1 日単位で集計します。すべての履歴は、保持期間が 90 日を超える場合は月単位、それ以外は日単位で集計します。

ダイアログは合計 Tokens、入力 Tokens、キャッシュ読み取り Tokens、出力 Tokens、呼び出し数、消費した Coin、傾向、モデル別内訳を表示します。モデル行は合計 Tokens の降順、次にモデル名の昇順で並びます。

消費した Coin は記録済みの課金の合計です。Monoize が現在の価格から過去の課金を再計算することはありません。すべての Key は**ウォレット残高に従う**と表示します。無効または期限切れの Key も履歴を読み取れます。
