## 開啟商店

在 `/dashboard/store` 開啟**商店**。選擇**餘額**、**方案**或**兌換碼**。

![Store](/images/en/store.webp)

使用貨幣控制項顯示人民幣或美元。此控制項會同時更新餘額、本月用量、價格、贈送、實得金額和方案額度。

Monoize 所有美元與人民幣的換算都使用固定匯率 1 美元 = 6.72 元。市場匯率變化不會改變餘額。

## 儲值餘額

1. 選擇儲值商品，或輸入自訂金額。
2. 檢查儲值金額、贈送金額和實得金額。
3. 選擇一個已啟用的付款 Channel。
4. 建立訂單。

Monoize 在聯絡 Provider 前儲存付款嘗試。Stripe 隨後開啟其託管的 Checkout 頁面。

易支付依所選方式回傳一個動作。QR Code 內容在付款對話框中顯示為可掃描的 QR Code。付款連結顯示一個動作，選取後跳轉。易支付只接受人民幣訂單。美元訂單請使用 Stripe。

Provider 結果未知時，不要建立另一個付款嘗試。等待 Monoize 對帳現有付款嘗試。

Checkout 結束後，商店每兩秒檢查一次訂單。付款和履約完成、訂單關閉或訂單過期後，檢查停止。

在 `/dashboard/orders` 查看訂單。分別檢查付款狀態和履約狀態。

Monoize 僅在驗證 Channel 付款後發放餘額。管理員不能把未付款訂單標記為已付款或已履約。

## 設定 Stripe 回呼

把 Stripe Webhook 端點設為 `https://lynshen.org/api/store/callbacks/{channel_id}`。使用 Stripe Channel ID 取代 `{channel_id}`。

訂閱 `checkout.session.completed` 和 `checkout.session.async_payment_succeeded`。把端點簽章密鑰儲存在加密的 Stripe 憑證中。

## 設定易支付

一個易支付 Channel 同時提供支付寶方式與微信支付方式。

把易支付非同步通知網址設為 `https://lynshen.org/api/store/callbacks/{channel_id}`。使用易支付 Channel ID 取代 `{channel_id}`。此端點接受文件規定的 `GET` 通知。

在商店管理中儲存閘道根位址、商戶 ID 和商戶金鑰。啟用支付寶方式、微信支付方式或兩者。閘道根位址必須以 `/` 結尾，且不得指向回送位址、連結本機位址或私有位址。

Monoize 對每個請求簽章：排除 `sign`、`sign_type` 和空值，依 ASCII 排序欄位，計算小寫 MD5。只有在驗證簽章、商戶 ID、訂單號、以分為單位的人民幣金額與預期方式，且付款狀態轉換提交之後，才回傳 `success`。

在 Channel 列上開啟**易支付方式**，設定每種方式的對外名稱、排序與啟用狀態。在此停用的方式不會出現在商店中。

## 購買方案

選擇方案和付款 Channel。一個方案可以同時套用多個額度週期。週期可以是 5 小時、12 小時、每日、每週、每月或自訂整數小時。

Monoize 以人民幣儲存方案額度。商店會把額度顯示為四捨五入後的整數人民幣或美元金額。

## 為 SQLite 啟用方案

變更 SQLite 配額 Gate 前，停止 Monoize 應用程式。把 `MONOIZE_DATABASE_DSN` 設為目標 SQLite 資料庫。

把已通過演練的 manifest 匯入 `next` 槽位：

```bash
monoize-store-ops quota-gate import --slot next --manifest ./quota-manifest.json
```

從命令輸出讀取相容性 fingerprint。啟動新應用程式版本前，推廣已匯入的 manifest：

```bash
monoize-store-ops quota-gate promote --expected-fingerprint <fingerprint>
```

此命令會拒絕 PostgreSQL、過大的 manifest、無效 JSON，以及與目前 SQLite 環境不相符的 manifest。

## 使用兌換碼

在**兌換碼**中輸入一個未使用的兌換碼。兌換碼可以增加餘額或啟用方案。兌換流程不使用付款 Channel，也不建立訂單。

## 管理商店

管理員開啟 `/dashboard/store-admin`。使用四個分頁管理商品、付款 Channel、訂單和兌換碼。

- 分別設定人民幣和美元的自訂儲值範圍。
- 新增易支付、Stripe 或 HTTP 草稿 Channel。使用內建圖示、HTTPS 圖片連結或上傳圖片。
- 開啟一個現有的易支付或 Stripe Channel。填寫全部憑證欄位和目前管理員密碼。選取**替換憑證**。Monoize 會加密新版本、停用舊版本並停用此 Channel。
- 在易支付 Channel 列上開啟 **Governance** 並選擇**易支付方式**，設定支付寶方式與微信支付方式。
- 在 Milestone 1 中保持 HTTP Channel 停用。
- 分別查看付款狀態和履約狀態。不要使用人工完成操作。
- 一次產生 1 至 20 個單次兌換碼。Monoize 顯示明文時立即保存。
- 在**付款管道**分頁頂部開啟**隱私記錄**和**資料保留**。
- 在易支付或 Stripe 的 Channel 列上開啟 **Governance**。選擇**支付合規**、**商戶能力**、**管道就緒狀態**或**易支付方式**。HTTP Channel 列不顯示該控制項。

## 檢視隱私記錄

正式環境的結帳和回呼需要一筆目前已接受的 Store 隱私記錄。複審間隔不得超過 365 天。

在 `/dashboard/store-admin` 開啟**商店管理**。選取**付款管道**分頁。選取**隱私記錄**。

![Store privacy records](/images/en/store-privacy-records.webp)

清單中的每筆記錄顯示政策版本、司法管轄區、允許區域、接受狀態和下次複審日期。記錄儲存後不能編輯。

核准政策更新後附加一筆記錄。填寫下列值，然後選取**新增隱私記錄**：

| 欄位 | 可接受的值 |
| --- | --- |
| **政策版本** | 1 至 64 位元組 |
| **司法管轄區** | 1 至 128 位元組 |
| **允許區域（逗號分隔）** | 1 至 32 個互不相同的值 |
| **法律依據** | 1 至 512 位元組 |
| **證據 SHA-256 摘要** | 恰好 64 個小寫十六進位字元 |
| **財務記錄保留天數** | 1 至 36500 |
| **過期授權保留小時數** | 1 至 24 |
| **複審間隔（天）** | 1 至 365 |

表單開啟時預填司法管轄區和允許區域 `CN`、財務記錄保留 2557 天（七年）、過期授權保留 24 小時、複審間隔 90 天。把每個值替換為政策核准的值。

Monoize 設定複審人、核准時間和下次複審日期。Monoize 也固定三個表單不提供的保留期：回呼原文 30 天、網路中繼資料 90 天、兌換稽核 730 天。

## 綁定管道治理

在支付合規、商戶能力和就緒設定完成之前，Channel 保持不可用。就緒設定必須引用一筆目前已接受的隱私記錄。

![Store payment Channels](/images/en/store-governance.webp)

在易支付或 Stripe 的 Channel 列上開啟 **Governance**。

1. 選取**支付合規**。審閱目前的 Store 付款條款。用管理員密碼確認條款。Monoize 取得一個 scope 為 `compliance_confirm` 的五分鐘重新驗證授權。
2. 選取**商戶能力**。為每項所需商戶能力記錄狀態、環境、管道商品、證據摘要和到期時間。
3. 選取**管道就緒狀態**。選取一筆**隱私記錄**。僅在簽章回呼測試通過後開啟**回呼驗證已通過**。設定支援的貨幣、結帳動作、每種貨幣的金額範圍，以及授權、執行和可用性證據摘要，再設定 1 至 90 天的有效期。選取**儲存**。

沒有任何隱私記錄時，就緒儲存按鈕保持停用。先在**隱私記錄**中新增一筆記錄。

每個 Channel 列顯示設定狀態和生效狀態。不可用的 Channel 會列出可讀原因標籤和原始原因代碼，例如隱私記錄待補、就緒設定缺失或過期、回呼驗證待完成、付款條款未確認，以及能力驗證缺口。

## 了解資料保留

Monoize 每天 03:00 UTC 在 Store Primary 上執行一次有界的保留工作。Replica 不執行該工作。每次執行使用啟動時目前已接受的隱私記錄。

下列保留期適用於全部記錄：

- 回呼原文：30 天。
- 網路中繼資料（來源 IP 和 User-Agent）：90 天。
- 兌換碼的檢視、複製和匯出稽核：730 天。
- 過期重新驗證授權雜湊：過期後再經過**過期授權保留小時數**。
- 財務記錄：**財務記錄保留天數**。

一次執行在五個資料類別中各最多檢查並修改 500 筆未被保留的根記錄：`raw_callback_bodies`、`network_metadata`、`financial_records`、`redemption_audits` 和 `expired_reauth_grants`。

前兩個資料類別清除欄位，而不刪除列。執行會清除已過期管道事件的加密原文，並清除超過 90 天的事件的來源 IP 和 User-Agent。事件列、原文摘要、解析後的事件、驗證結果和投影狀態保持不變。

刪除一筆財務根記錄時，同時刪除其付款嘗試、事件套用、退款、退款查詢重試、獎勵回收列和追償聲明列。執行會保留有效權益及其發放記錄。

每次執行在一個交易中完成。失敗時回復該次執行的全部刪除。對未變更的資料重複執行，不改變已清除的欄位，也不會因上次執行已刪除候選記錄而失敗。

付款資料、回呼證據、備份、記錄檔和加密金鑰保留在隱私記錄的允許區域內。每一次證據讀取、匯出、保留覆寫和法律保留操作都寫入一筆不可變存取稽核，記錄操作者、角色、範圍、原因、時間和結果。

## 手動執行保留工作

開啟**商店管理**。選取**付款管道**分頁。選取**資料保留**。

![Store retention](/images/en/store-retention.webp)

對話框顯示連續失敗次數、結帳狀態（**正常接單**或**已暫停**）、保留工作數和法律封存數。它還會說明：執行後將永久刪除超出保留期限的記錄。

填寫**目前密碼**和**原因**。任一欄位為空時，執行按鈕保持停用。選取**執行保留工作**。Monoize 取得一個 scope 為 `retention_operation` 的五分鐘重新驗證授權，並啟動一次有界執行。

已有執行進行中時，請求回傳 HTTP `409` 和代碼 `retention_run_active`。執行成功把連續失敗次數重設為零。執行失敗或被中斷則遞增該計數。

## 套用法律封存

法律封存在一個資料類別中暫停刪除指定的識別碼。**資料保留**對話框顯示法律封存數。它不建立法律封存。

使用 `POST /api/dashboard/store/admin/retention/legal-holds` 建立法律封存。該請求需要管理員工作階段、Store Primary，以及一個 scope 為 `legal_hold` 的五分鐘重新驗證授權。JSON 請求主體必須包含 `data_class`、`identifiers`、`reason`、`requesting_authority`、`requester_id`、`approver_role`、`expires_at` 和 `extends_hold_id`。

- `data_class` 必須是五個保留資料類別之一。
- `identifiers` 必須包含 1 至 100 個互不相同的值。每個值最多 255 位元組。
- `approver_role` 必須是 `privacy` 或 `legal`。
- `requester_id` 必須不同於已驗證的管理員。該管理員是核准人。
- `expires_at` 必須是未來的 RFC3339 時刻。
- 初次核准時 `extends_hold_id` 必須為 `null`。延期必須引用資料類別和識別碼完全相同的法律封存，並使用更晚的到期時間。

法律封存在其開始時間不晚於評估時間、且評估時間早於其到期時間時生效。到期自動結束封存，不需要任何操作。法律封存不還原已刪除的資料。任何操作都不更新、刪除、重新啟用或修改已儲存的封存列。延期會插入一筆新的法律封存和一筆新的核准稽核。

## 解除結帳暫停

某次執行失敗後連續失敗次數達到三次，且結帳尚未暫停時，Monoize 建立一筆嚴重保留警示並暫停結帳。

結帳暫停期間，新訂單和新付款嘗試回傳 HTTP `503` 和代碼 `store_retention_paused`。對既有訂單或終態付款嘗試的等冪重放仍可回傳其原有結果。回呼接收、對帳、退款和保留操作保持可用。

應用程式重新啟動會保留該計數、警示和暫停狀態。僅有一次成功執行不會解除暫停。

開啟**資料保留**解除暫停。僅在結帳暫停時，對話框才顯示**證據 SHA-256 摘要**欄位。它還會說明：送出後將清除目前警示並立即恢復結帳。填寫**目前密碼**、**原因**和該摘要。密碼與原因為空、或摘要不是恰好 64 個字元時，處理按鈕保持停用。選取**處理警示**。

Monoize 記錄處理結果、把警示標記為已處理並恢復結帳。處理警示不改變連續失敗次數。後續再次執行失敗可以再次暫停結帳。沒有作用中且未處理的警示時，處理請求回傳 HTTP `409` 和代碼 `retention_containment_unavailable`。
