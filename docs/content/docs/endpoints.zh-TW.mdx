## 基礎 URL 與認證

將請求發送到 Monoize 的監聽位址。預設為 `http://localhost:8080`。使用以下任一請求標頭攜帶 API 金鑰：

```bash
Authorization: Bearer sk-...
# 或
x-api-key: sk-...
```

下列每個端點都有 `/api` 前綴別名，例如 `/api/v1/chat/completions`。當用戶端硬編碼了 `/api` 路徑時使用別名。將網站根網址作為 API Base URL 的用戶端可以省略 `/v1`，例如 `/responses`。

任何端點都可以到達任何上游類型。例如，用戶端呼叫 `/v1/messages`，而路由透過 `chat_completion` 類型的 Channel 服務該模型。Monoize 在兩個方向上轉換協議。

## 協議轉換

多個工具使用相同名稱時，請使用 Responses 工具命名空間。選定的 Channel 使用 Chat Completions、Messages 或 Gemini 時，Monoize 會保留工具身分。

跨服務商傳遞檔案時，請提供檔案內容或公開 URL。私有檔案參照必須符合唯一的 Provider、Channel 和憑證範圍。

請將圖片遮罩與原圖一起提交。圖片轉換會保留遮罩尺寸和透明度。

目標協議無法表示回應中的媒體時，介面會傳回明確錯誤。串流回應會以錯誤結束，不會傳送成功結束事件。

Gemini 轉換會保留支援的取樣參數、引用、工具簽章和用量明細。協議專屬欄位只會傳送至相容的目標協議。

## 列出模型

```bash
curl http://localhost:8080/v1/models \
  -H "Authorization: Bearer sk-..."
```

回應以 OpenAI 列表格式返回呼叫金鑰可用的邏輯模型。

## Chat Completions

```bash
curl http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-model",
    "messages": [{ "role": "user", "content": "Hello" }],
    "stream": true
  }'
```

設定 `"stream": true` 使用伺服器推送事件。省略或設為 `false` 則返回單一 JSON 回應。

## Responses

```bash
curl http://localhost:8080/v1/responses \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-model",
    "input": "Hello",
    "stream": true
  }'
```

說明：

- 當上游提供伺服器端狀態時，Monoize 支援 `previous_response_id` 鏈。開啟工作階段親和可以讓後續請求到達同一個 Channel。參見[路由與可靠性](/zh-TW/docs/routing)。
- `GET /v1/responses` 會升級為 WebSocket 傳輸，供使用該傳輸的用戶端呼叫。
- `GET /v1/codex/responses` 與 `GET /v1/responses` 使用同一個 WebSocket 處理器。`POST /v1/codex/responses` 與 `POST /v1/responses` 使用同一個 HTTP 處理器。兩個路徑也有 `/api` 別名。
- `POST /v1/responses/compact` 壓縮一段會話。

向 Responses 上游轉送請求時，Monoize 保留明確傳入的 `include` 和 `reasoning.summary`。它不會自動加入 `reasoning.encrypted_content` 或預設摘要設定。

## Anthropic Messages

```bash
curl http://localhost:8080/v1/messages \
  -H "x-api-key: sk-..." \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-model",
    "max_tokens": 1024,
    "messages": [{ "role": "user", "content": "Hello" }]
  }'
```

## Embeddings

```bash
curl http://localhost:8080/v1/embeddings \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-embedding-model",
    "input": "The quick brown fox"
  }'
```

## 圖像

透過 Responses Channel 呼叫圖像端點前，請設定 `image_enable_openai_generation_tool`。缺少必要工具時，請求會在轉送前傳回錯誤。

生成：

```bash
curl http://localhost:8080/v1/images/generations \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-image-model",
    "prompt": "A lighthouse at dawn",
    "size": "1024x1024"
  }'
```

編輯使用 `multipart/form-data`：

```bash
curl http://localhost:8080/v1/images/edits \
  -H "Authorization: Bearer sk-..." \
  -F model="my-image-model" \
  -F prompt="Add a red boat" \
  -F image[]=@input.png
```

## 使用官方 SDK

將官方 SDK 的基礎 URL 指向 Monoize：

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8080/v1",
    api_key="sk-...",
)
```

```python
import anthropic

client = anthropic.Anthropic(
    base_url="http://localhost:8080",
    api_key="sk-...",
)
```

## 錯誤回應

| HTTP 狀態碼 | 錯誤碼 | 含義 |
| --- | --- | --- |
| `401` | `unauthorized` | API 金鑰缺失、無效、被停用或已過期 |
| `402` | `insufficient_balance` | 使用者或子帳戶餘額不足 |
| `402` | `api_key_spend_limit_reached` | 金鑰的消費限額視窗(總額、每小時或每日)已用盡 |
| `403` | `model_not_allowed` | 金鑰的模型限制拒絕了請求的模型 |
| `403` | `ip_not_allowed` | 用戶端 IP 不在金鑰的 IP 白名單中 |
| `502` | `upstream_error` | 沒有路由服務該模型，或所有符合條件的路由都失敗 |

上游錯誤文字在到達用戶端之前會被遮罩。完整詳情請在[請求日誌](/zh-TW/docs/request-logs)中檢視。
