## ログ一覧

サイドバーの**ログ**を開きます。Monoize は API キーで認証されたすべての転送リクエストを 1 行ずつ記録します。各行には次の情報が表示されます。

- 論理モデルと API キー名。管理者には処理した Provider と Channel も表示されます。
- トークン数: 入力、出力、キャッシュ読み取り、キャッシュ作成、推論トークン
- 米ドル建ての課金額
- ステータス: `pending`、`success`、`error`、`client_gone`
- タイミング: 合計時間、最初のバイトまでの時間、ストリームの秒間トークン数

逐次転送されるストリームでは、上流の最初の完全な SSE イベントを受信すると、リアルタイムの `pending` 行に TTFB が表示されます。
開始、使用量、エラーのイベントでも、本文の到着前にこの値が設定されます。ハートビートのコメントでは設定されません。
TTFB は上流の最初のイベントまでの時間です。最初の文字が表示されるまでの時間ではありません。
この更新はメモリ内で行います。最終的な使用量と課金結果はリクエスト終了後に保存します。

`client_gone` は、レスポンス完了前にクライアントが切断し、その後上流リクエストが正常に完了したことを示します。
Monoize は上流の処理を継続し、記録した使用量に基づいて通常どおり課金します。
クライアントがプロトコルの完了フレームを受信して読み取りを停止した場合、正常なリクエストは `success` のままです。
HTTP 接続の終了前や課金確定前でも、この規則が適用されます。
上流 API エラーと課金確定エラーは `error` のままです。

一覧ではリアルタイム更新が既定で有効です。**リアルタイム更新**を無効にすると、イベントストリームとフォールバックポーリングが停止します。**更新**を使用して一覧を手動更新します。

## 実際の上流モデル

`admin` または `super_admin` アカウントでは、上流レスポンスのモデル名が異なる場合、モデルバッジの後ろに同じ行で表示されます。
モデルバッジまたは Channel にポインターを合わせて、**実際のモデル**を確認してください。
この値はレスポンス変換前の上流レスポンスから取得します。
Monoize は、リクエスト変換後に上流へ送信したモデル名と比較します。
名前が一致する場合、またはレスポンスにモデル名がない場合、この値は表示されません。
他のロールには、この値は送信も表示もされません。
論理モデルと課金の選択は変わりません。

## 失敗した試行

リクエストが複数回の上流試行を要した場合、その行は失敗した各ホップを順番に一覧表示します。各ホップには Provider、Channel、上流のステータスコード、エラーテキストが表示されます。この一覧で、どの Channel が失敗し、なぜリクエストが次へ進んだかを確認できます。

## リクエストキャプチャ

キャプチャは各上流試行の正確なペイロードをディスクに保存します。キャプチャはデフォルトで無効です。2 つのスイッチで制御します。

1. **システムスイッチ。** `super_admin` が**設定**でリクエストキャプチャを有効にします。このスイッチが無効の間は、どのキーでもキャプチャは書き込まれません。
2. **キー単位のモード。** 各 API キーが `request_capture_mode` を設定します。
   - `off`: キャプチャしない。
   - `capture-all`: 上流に到達したすべてのリクエストをキャプチャする。
   - `capture-only-abnormal`: 失敗、使用量の欠落、使用量ゼロ、または複数回のアップストリーム試行があるリクエストをキャプチャする。

キャプチャファイルには保持期間があります。デフォルトは 1 日です。**設定**の `monoize_request_capture_retention_days` で変更できます。

## キャプチャビューア

キャプチャが保存された行にはキャプチャインジケーターが表示されます。クリックするとビューアが開きます。ビューアは試行ごとに次を表示します。

- 元の下流リクエストボディ
- すべての変換適用後のリクエスト
- 上流に送信された正確なエンコード済みリクエスト
- 上流の生レスポンスまたはストリームフレーム
- 実行された変換チェーン（スコープと順序付き）

`user` ロールは自分のキャプチャのみ閲覧でき、API キースコープの変換エントリのみ表示されます。管理者は `user` ロールのアカウントが所有するキャプチャを閲覧できます。

## トラブルシューティング

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 新しい行にキャプチャインジケーターがない | キャプチャの永続化がライブ行の到着より遅い | 一覧の自動更新を待つか、一度再読み込みする |
| `capture_not_found` | キャプチャの期限切れ、またはロールに閲覧権限がない | 保持日数を増やすか、所有者に確認する |
| 特定キーの行が表示されない | そのキーは別のユーザーの所有 | キー所有者または管理者としてサインインする |
