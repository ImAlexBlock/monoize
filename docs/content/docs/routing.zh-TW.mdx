## 路由選擇

對每個請求，Monoize 按以下順序解析路由：

1. **模型重新導向。** 先執行 API 金鑰規則，再執行全域規則。第一條匹配的規則重寫模型名。
2. **Provider 選擇。** Monoize 收集 API 金鑰允許的 Group 中，已啟用且透過內嵌 Channel 對應該模型並具備完整價格的 Provider。
3. **Channel 選擇。** 每個 Provider 只有一個內嵌 Channel。該 Channel 已啟用且健康時，Monoize 使用它。

## 重試與備援

Monoize 先嘗試所選 Provider 的 Channel，再前進到同一 Group 中的下一個 Provider。

- 每個 Channel 獲得 `channel_max_retries + 1` 次嘗試。預設為 1 次嘗試，不做 Channel 內重試。
- `channel_retry_interval_ms` 在 Channel 內重試之間插入等待。預設為 `0`。
- 一個 Provider 耗盡後，Monoize 繼續嘗試下一個符合條件的 Provider。
- 所有 Provider 都耗盡後，用戶端收到 HTTP `502`，錯誤碼為 `upstream_error`。

### 哪些錯誤會重試同一 Channel

| 錯誤 | 同 Channel 重試 | 前進到下一路由 |
| --- | --- | --- |
| HTTP `408`、`429`、`5xx` | 是 | 是，Channel 預算耗盡後 |
| 逾時、連線被拒絕或重設 | 是 | 是，Channel 預算耗盡後 |
| 其他上游錯誤（如 `400`、`401`、`404`） | 否 | 是，立即前進 |
| Monoize 自身錯誤（認證、餘額、驗證、計費） | 否 | 否；路由終止 |

### 回退到金鑰最近使用的模型

請求的模型沒有可用路由，或所有路由在產生任何輸出前都失敗時，Monoize 會換一個模型重試一次。

- 回退模型是該 API 金鑰最近 24 小時內最後一次成功請求所用的模型，且不是本次請求的模型。
- 金鑰沒有這樣的請求、金鑰的模型限制不允許該模型，或用戶端已中斷連線時，Monoize 不重試。
- 重試不會再次回退。重試依回退模型的價格計費。
- 請求日誌會有兩列：失敗的請求與重試。重試的請求 ID 以 `-fallback` 結尾。

這讓用戶端的輔助任務能繼續運作。例如 Codex 會用 `gpt-6-luna` 產生對話標題；若沒有路由提供該模型，請求會改用你的主要模型。

## 串流保證

第一個回應位元組到達用戶端時，備援即結束。在此之前，Monoize 可以自由切換 Channel 和 Provider。在此之後，Monoize 絕不切換。因此可見的串流始終來自同一次生成。

## 串流逾時

使用 `monoize_stream_idle_timeout_ms` 限制兩次上游串流事件之間的等待時間。預設值為 `120000` 毫秒。

Monoize 等待回應標頭的時限為有效 `request_timeout_ms` 的十倍，且不低於 `600000` 毫秒。
讀取上游 HTTP 錯誤回應本文時共用此時限。
收到成功回應標頭後，持續輸出的串流沒有總時長限制。
此規則也適用於影像串流，以及收集後轉為非串流回應的上游串流。
非串流上游請求仍受總請求逾時限制。

## 斷路器

每個 Provider 有 `circuit_breaker_enabled` 開關。啟用時：

- 一個 Channel 在 `window_seconds`（預設 `30`）內出現 `failure_count_threshold`（預設 `3`）次可重試失敗後變為不健康。
- 不健康的 Channel 在 `cooldown_seconds`（預設 `60`）內被跳過。由 HTTP `429` 引起的失敗使用 `rate_limit_cooldown_seconds`（預設 `15`）。
- 開啟 `per_model_circuit_break` 後，健康狀態按 `(Channel, 模型)` 組合追蹤，而不是按 Channel。
- 開啟主動探測後，Monoize 在背景探測冷卻結束的 Channel，達到成功閾值後恢復。

將 Provider 的 `circuit_breaker_enabled` 設為 `false` 可忽略其健康狀態。該 Provider 的被動熔斷和主動探測隨之停止。

## 工作階段親和

Monoize 可以把一個工作階段綁定到服務它的 Channel，讓攜帶伺服器端狀態的後續請求（例如 Responses 的 `previous_response_id`）到達同一個上游。親和可以全域設定，也可以按 Channel 設定。被親和優先的 Channel 仍然遵守資格和健康規則。

## 時間指標

[請求日誌](/zh-TW/docs/request-logs)中的每一行記錄總耗時、首位元組時間和可見輸出的每秒 Token 數。修改 Group 優先級之前，用這些數值比較 Provider。
