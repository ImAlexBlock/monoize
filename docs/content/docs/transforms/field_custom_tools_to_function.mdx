---
title: "Field: custom tools to function"
description: Convert selected custom tools to JSON functions for an upstream that does not support custom tools. Restore converted calls in the response.
---

## When to use

Enable this transform when an upstream rejects `type: custom` but accepts JSON `function` tools.
For example, convert a client's freeform `apply_patch` tool for that upstream.
Keep the Channel protocol setting consistent with the upstream endpoint.
This transform changes tool definitions; it does not change the selected protocol or URL.

Add two rules with the same model filter and configuration: one `request` rule and one `response` rule.
The response rule restores only tools converted during the current upstream attempt.
A response rule alone does not convert ordinary function calls.

## Behavior

The request rule converts selected custom tools, including tools inside `namespace.tools`, to JSON functions.
It wraps each original custom input string in a required string field named `input`.
It preserves that entire string, even when the string contains JSON.
It also updates matching tool history, correlated results, and `tool_choice`, including selections inside `allowed_tools`.

The response rule restores the converted calls and unwraps their `input` strings.
If the complete arguments are a JSON string, it decodes that string.
It tracks the namespace and name for each conversion.
Ordinary function tools remain function tools, including when `names` contains `"*"`.
Declaring a function and a selected custom tool with the same namespace and name rejects the request before forwarding.
If an upstream omits a namespace, Monoize restores it only when the tool name identifies one distinct tool in the request.

The converted function does not retain custom grammar enforcement, including Lark constraints.
Use this transform only when a string argument is acceptable for the selected tool.

### Streaming

Arguments for converted calls are buffered until each call completes.
Monoize then emits the complete custom input string.
Split JSON escapes and wrapper fragments do not appear as custom input fragments.
Text and reasoning continue to stream normally.
Ordinary function arguments also stream normally when the upstream identifies the tool in its start event.
If a tool starts without a name and the request has matching conversions, Monoize delays its events until tool or response completion.
It then restores converted calls or replays the original events for ordinary functions.
This processing preserves usage and metadata.
A stream error discards incomplete buffered arguments.

### apply_patch formatting

For a converted `apply_patch` call, the response rule normalizes the complete patch text:

- Normalize patch markers to `*** Begin Patch` and `*** End Patch`.
- Remove `*** End of File` markers and an outer `<invoke>` wrapper.
- Prefix raw Add File content lines with `+`. Preserve lines already starting with `+`, `-`, or `\`.
- Stop Add File prefixing at `@@` headers or a different patch section. Preserve Update File deletions.
- Remove Update File hunks with identical deleted and inserted lines when the hunk has no context line.

The request schema includes these patch instructions only for `apply_patch`.
Other tools receive a general string-input schema.

## Reference

| Property | Value |
| --- | --- |
| Type ID | `field_custom_tools_to_function` |
| Phase | `request`, `response` |
| Scopes | Provider, Global, API key |

## Configuration

| Option | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `names` | string[] | No | `["apply_patch"]` | Exact custom tool names to convert. An empty array disables conversion. `"*"` selects every custom tool. Empty strings are invalid. |

### Example rules

Replace `target-model` with the model that needs this conversion.
Use both rules together.

```json
[
  {
    "transform": "field_custom_tools_to_function",
    "enabled": true,
    "phase": "request",
    "models": ["target-model"],
    "config": { "names": ["apply_patch"] }
  },
  {
    "transform": "field_custom_tools_to_function",
    "enabled": true,
    "phase": "response",
    "models": ["target-model"],
    "config": { "names": ["apply_patch"] }
  }
]
```

To convert every custom tool, set `"names": ["*"]` in both rules.
This setting preserves ordinary function tools.
