title: "Auto-cache: OpenAI tool results"
description: Insert explicit prompt-cache breakpoints on tool-result blocks for GPT models.

## What it does

This transform inserts explicit OpenAI prompt-cache breakpoints on eligible tool-result content blocks. It targets GPT model families that support explicit cache breakpoints.

Requests without eligible tool-result blocks pass through unchanged.

## Unsupported upstreams

Some relays serve a GPT model name from a backend that rejects the breakpoint field. Such an upstream returns HTTP 400 with `prompt_cache_breakpoint is not supported on this model`.

Monoize handles this rejection automatically:

1. Monoize removes every `prompt_cache_breakpoint` key from the request body.
2. Monoize sends the request again to the same upstream once. The client does not see the first failure.
3. Monoize remembers the upstream base URL and model for one hour. During that hour, Monoize removes the key before the first send.

Some upstreams return HTTP 200 and send the rejection as the first stream event. Monoize reads the first event before it forwards the stream, and handles this case the same way.

The memory is local to each process. A restart clears it. For a permanent fix, disable this transform on the affected Provider.

## Reference

| Property | Value |
| --- | --- |
| Type ID | `cache_openai_tool_use` |
| Phase | `request` |
| Scopes | Provider, Global, API key |

## When to use

- Agent clients run tool loops against an OpenAI-compatible upstream with explicit-breakpoint support.
- You want the tool-loop prefix cached between iterations.

## Configuration

This transform has no options. Use an empty `config` object.

### Example rule

```json
{
  "transform": "cache_openai_tool_use",
  "enabled": true,
  "phase": "request",
  "models": [
    "gpt-*"
  ],
  "config": {}
}
```
