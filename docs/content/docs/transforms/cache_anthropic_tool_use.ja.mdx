---
title: "自動キャッシュ: Anthropic ツール結果"
description: 最後のツール結果に cache_control を設定します。
---

リクエスト単位のキャッシュ設定は、4 個のキャッシュ枠のうち 1 個を使います。明示的なノードのブレークポイントも 1 個を使います。4 個に達すると、これらの変換はマーカーを追加しません。

## 動作

リクエストがツール結果を送信するとき、この変換は最後のツール結果に Anthropic の ephemeral `cache_control` を追加します。ツール結果を送信するたびにキャッシュ位置が前へ進みます。

ツール結果のないリクエストは変更されずに通過します。

## リファレンス

| 項目 | 値 |
| --- | --- |
| タイプ ID | `cache_anthropic_tool_use` |
| フェーズ | `request` |
| スコープ | Provider, API キー |

## 使いどころ

- エージェントクライアントが Anthropic 互換の上流で長いツールループを実行する。
- 各反復で会話プレフィックスを全額の入力価格ではなくキャッシュから再読するようにしたい。

## 設定

| オプション | 型 | 必須 | デフォルト | 説明 |
| --- | --- | --- | --- | --- |
| `ttl` | string | いいえ | `"5m"` | `5m` または `1h`。挿入するブレークポイントのキャッシュ有効期間です。`5m` は `{"type": "ephemeral"}` を送信し、`1h` は `"ttl": "1h"` を追加します。 |

`1h` を有効にする前に、選択した Provider の料金を確認してください。キャッシュ書き込み料金には、設定された課金 Profile を使用します。

`1h` ブレークポイントが `5m` ブレークポイントの後にあると、Anthropic はリクエストを拒否します。すべての Anthropic `cache_*` ルールで同じ `ttl` を使うか、`1h` は前方のブレークポイントだけに使ってください。

Provider ルールは API キールールより先に実行されます。後から実行されるルールは Monoize が挿入したブレークポイントの TTL を書き換えるため、API キールールが Provider ルールより優先されます。クライアントが送信した `cache_control` は変更されません。ノードを編集または並べ替える変換は、キャッシュルールより先に実行してください。対象が変わると、後続ルールは元のマーカーを上書きしません。同一内容のノードも区別できないため、マーカーの所有情報を破棄します。

### ルール例

```json
{
  "transform": "cache_anthropic_tool_use",
  "enabled": true,
  "phase": "request",
  "models": [
    "claude-*"
  ],
  "config": { "ttl": "1h" }
}
```
