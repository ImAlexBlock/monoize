## 動作

この変換は、対象となるツール結果コンテンツブロックに明示的な OpenAI プロンプトキャッシュブレークポイントを挿入します。明示的ブレークポイントをサポートする GPT モデルファミリーが対象です。

対象ブロックのないリクエストは変更されずに通過します。

## ブレークポイント非対応の上流

一部の中継サービスは、同じ GPT モデル名をブレークポイント非対応のバックエンドで提供します。この上流は HTTP 400 と `prompt_cache_breakpoint is not supported on this model` を返します。

Monoize はこの拒否を自動で処理します。

1. リクエスト本文からすべての `prompt_cache_breakpoint` キーを削除します。
2. 同じ上流へリクエストを 1 回だけ再送します。クライアントには最初の失敗が見えません。
3. その上流の base URL とモデルを 1 時間記憶します。この間は最初の送信前にキーを削除します。

一部の上流は HTTP 200 を返し、拒否をストリームの最初のイベントとして送ります。Monoize はストリームを転送する前に最初のイベントを読み、同じ方法で処理します。

この記憶はプロセスごとのメモリにあり、再起動で消えます。恒久的に解決するには、対象の Provider でこの変換を無効にします。

## リファレンス

| 項目 | 値 |
| --- | --- |
| タイプ ID | `cache_openai_tool_use` |
| フェーズ | `request` |
| スコープ | Provider, グローバル, API キー |

## 使いどころ

- エージェントクライアントが明示的ブレークポイント対応の OpenAI 互換上流でツールループを実行する。
- ツールループのプレフィックスを反復のあいだキャッシュしたい。

## 設定

この変換にはオプションがありません。`config` には空オブジェクトを指定します。

### ルール例

```json
{
  "transform": "cache_openai_tool_use",
  "enabled": true,
  "phase": "request",
  "models": [
    "gpt-*"
  ],
  "config": {}
}
```
