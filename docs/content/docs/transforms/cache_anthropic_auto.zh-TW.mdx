---
title: "自動快取：Anthropic 請求"
description: 為 Anthropic Messages 請求啟用頂層自動快取。
---

請求層級的快取設定占用四個快取槽位中的一個。每個明確的節點斷點占用一個槽位。達到四個槽位後，這些轉換不再新增標記。

## 行為

此變換會在請求 JSON 頂層加入 `cache_control`。上游會在對話增長時，將快取斷點移到最後一個可快取內容區塊。用戶端提供的 `cache_control` 值保持不變。

## 參考資訊

| 屬性 | 值 |
| --- | --- |
| Type ID | `cache_anthropic_auto` |
| Phase | `request` |
| Scopes | Provider, API key |

## 適用場景

當 Channel 接受 Anthropic 自動快取時使用。保留 `cache_anthropic_system` 以快取穩定的系統前綴。確認透傳服務接受頂層欄位。

## 配置

| 選項 | 類型 | 必填 | 預設值 | 說明 |
| --- | --- | --- | --- | --- |
| `ttl` | string | 否 | `"5m"` | `5m` 或 `1h`。插入的快取斷點的有效期。`5m` 發送 `{"type": "ephemeral"}`，`1h` 額外加入 `"ttl": "1h"`。 |

啟用 `1h` 前，請檢查所選 Provider 的定價。快取寫入費用使用已設定的計費 Profile。

`1h` 斷點位於 `5m` 斷點之後時，Anthropic 會拒絕請求。所有 Anthropic `cache_*` 規則應使用相同的 `ttl`，或只在靠前的斷點上使用 `1h`。最後一個區塊已有 TTL 不同的顯式 `cache_control` 時，Anthropic 也會拒絕請求。

Provider 規則先於 API 金鑰規則執行。後執行的規則會改寫 Monoize 已插入斷點的 TTL，因此 API 金鑰規則覆蓋 Provider 規則。用戶端自帶的 `cache_control` 始終保持不變。請在快取規則之前執行修改或重排節點的變換。目標變更後，後續規則不再覆蓋原有標記。內容完全相同的節點也不保留標記歸屬，以免誤改用戶端標記。

```json
{
  "transform": "cache_anthropic_auto",
  "enabled": true,
  "phase": "request",
  "models": ["claude-*"],
  "config": { "ttl": "1h" }
}
```
